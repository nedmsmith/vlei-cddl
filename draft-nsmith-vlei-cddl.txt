5.  CDDL Schema

   The CDDL fragments below collectively define the vLEI credential
   schemas.  The root fragment defines the top-level credential choice;
   the remaining fragments define credential-specific properties and the
   shared identifiers, node references, and disclaimer types used by
   those credentials.

5.1.  vLEI Credential Types

   The top-level vLEI defines the supported vLEI credential types.

   ; ------------------------------------------------------------
   ; vLEI CDDL Schema
   ; ------------------------------------------------------------

   vlei-cred =
       lei-cred /
       oor-cred /
       ecr-cred /
       qvi-cred /
       oor-auth-cred /
       ecr-auth-cred /
       ixbri-cred

5.2.  Legal Entity vLEI Credential

   The Legal Entity credential defines issuer, subject, edge, and rule
   blocks.

5.2.1.  Top-level Credential Definition

   ; Legal Entity vLEI Credential

   lei-cred = [
       lei-boilerplate,
       lei-properties
   ]

5.2.2.  Credential Properties

   ; ============================================================
   ; LEI Properties Block
   ; ============================================================
   ; Top-level properties for Legal Entity vLEI Credential

   lei-properties = {
   ; structural attributes
       v: tstr,  ; Version
       d: said,  ; Credential SAID
       u: tstr,  ; One time use high entropy nonce
       i: aid,   ; Credential Issuer - a QVI entity
       ri: tstr, ; Credential status registry
       s: said,  ; SAID of this lei schema
   ; subject attributes
       a: lei-a,
   ; edge properties
       e: lei-e,
   ; rule properties
       r: lei-r
   }

5.2.3.  Credential Boilerplate

   ; ============================================================
   ; LEI Boilerplate
   ; ============================================================
   ; Legal Entity vLEI Credential boilerplate metadata

5.9.  Shared Types and Disclaimers

   The shared fragment defines identifier types, node and schema
   references, and canonical disclaimer text.  The SAID type is imported
   from the IETF SAID specification.

5.9.1.  SAID Type

   The SAID (Self-Addressed Identifier Digest) type is imported from the
   IETF SAID specification and supports multiple representation
   profiles.

   ; The shared type is extended by the supported representation profiles.
   said = $said
   $said /= said-cbor
   $said /= said-json
   $said /= said-cesr
   $said /= said-urn
   ; The URN representation is a CESR digest prefixed with "urn:cesr:said:".
   ; The URN payload is the CESR text defined by said-cesr.
   said-urn = $said-urn
   $said-urn /= "urn:cesr:said:" .cat said-cesr
   ; CBOR can carry a CESR representation or an algorithm/digest tuple.
   said-cbor = $said-cbor
   $said-cbor /= said-cesr
   $said-cbor /= said-alg-digest

   ; hash-alg-id is from the IANA Named Information Hash Algorithm Registry.
   said-alg-digest = [
     hash-alg-id: int
     hash-value: bstr
   ]
   ; JSON can carry CESR text or an algorithm/digest object.
   said-json = $said-json
   $said-json /= said-cesr
   $said-json /= said-json-alg-digest

   ; JSON uses a hash-algorithm name and an unpadded base64url digest.
   said-json-alg-digest = {
     hash-alg-id: tstr
     hash-value: tstr .regexp "[A-Za-z0-9_-]+"
   }
   ; CESR text is a digest-algorithm code followed by encoded digest text.
   said-cesr = $said-cesr
   $said-cesr /= said-cesr-256
   $said-cesr /= said-cesr-512

   said-cesr-256 = $said-cesr-256
   $said-cesr-256 /= "E" .cat said-cesr-256-text ; Blake3-256
   $said-cesr-256 /= "F" .cat said-cesr-256-text ; Blake2b-256
   $said-cesr-256 /= "G" .cat said-cesr-256-text ; Blake2s-256
   $said-cesr-256 /= "H" .cat said-cesr-256-text ; SHA3-256
   $said-cesr-256 /= "I" .cat said-cesr-256-text ; SHA2-256
   said-cesr-256-text = (tstr .size 43) .regexp "[A-Za-z0-9_-]+"

   said-cesr-512 = $said-cesr-512
   $said-cesr-512 /= "0D" .cat said-cesr-512-text ; Blake3-512
   $said-cesr-512 /= "0E" .cat said-cesr-512-text ; Blake2b-512
   $said-cesr-512 /= "0F" .cat said-cesr-512-text ; SHA3-512
   $said-cesr-512 /= "0G" .cat said-cesr-512-text ; SHA2-512
   said-cesr-512-text = (tstr .size 86) .regexp "[A-Za-z0-9_-]+"

5.9.2.  Core Primitives

   Core data type primitives including identifiers, maps, and date-time
   values used across all vLEI credentials.

   ; ============================================================
   ; Common Primitives
   ; ============================================================
   ; Core data type primitives used across all vLEI credentials

   said-map = { d: said }
   aid-map = { i: aid }

   aid = tstr / bstr     ; an AID-like inception event digest identifier
   date-time = tstr      ; RFC3339-compatible date-time text

5.9.3.  Node-Schema Pairs

   Schema node pairs for linking credentials to their schemas, with both
   generic and credential-specific variants.

   ; ============================================================
   ; Node-Schema Pairs
   ; ============================================================
   ; Schema node pairs for linking credentials to their schemas

   node-schema-pair = {
     n: said    ; node SAID (issuer credential SAID)
     s: said    ; schema SAID (SAID of required schema)
   }

   ; schema specific node-schema-pair for QVI Issuer's Credential
   node-schema-pair-qvi = {
     n: said
     s: "EBfdlu8R27Fbx-ehrqwImnK-8Cm79sqbAQ4MmvEAYqao"
   }

   ; schema specific node-schema-pair for LE Issuer's Credential
   node-schema-pair-le = {
     n: said
     s: "ENPXp1vQzRF6JwIuS-mp2U8Uf1MoADoP_GqQ62VsDZWY"
   }

   ; ixbri OOR variant that fixes s to the EBNaNu... SAID
   node-schema-pair-oor-ixbri = {
     n: said
     s: "EBNaNu-M9P5cgrnfl2Fvymy4E_jvxxyjb70PRtiANlJy"

   ; ixbri ECR variant (fixes s to EEy9...)

5.9.5.  Disclaimer Text Constants

   Canonical literal text for disclaimers including usage, issuance, and
   privacy considerations.

   ; ============================================================
   ; Disclaimer Texts
   ; ============================================================
   ; Canonical legal disclaimer text for vLEI credentials

   ; canonical literals for each disclaimer
   usage-disclaimer-text = "Usage of a valid, unexpired, and non-revoked vLEI Credential, as defined in the associated Ecosystem Governance Framework, does not assert that the Legal Entity is trustworthy, honest, reputable in its business dealings, safe to do business with, or compliant with vlei-any laws or that an implied or expressly intended purpose will be fulfilled."

   issuance-disclaimer-text = "All information in a valid, unexpired, and non-revoked vLEI Credential, as defined in the associated Ecosystem Governance Framework, is accurate as of the date the validation process was complete. The vLEI Credential has been issued to the legal entity or person named in the vLEI Credential as the subject; and the qualified vLEI Issuer exercised reasonable care to perform the validation process set forth in the vLEI Ecosystem Governance Framework."

   privacy-disclaimer-text = "Privacy Considerations are applicable to QVI ECR AUTH vLEI Credentials.  It is the sole responsibility of QVIs as Issuees of QVI ECR AUTH vLEI Credentials to present these Credentials in a privacy-preserving manner using the mechanisms provided in the Issuance and Presentation Exchange (IPEX) protocol specification and the Authentic Chained Data Container (ACDC) specification.  https://github.com/WebOfTrust/IETF-IPEX and https://github.com/trustoverip/tswg-acdc-specification."

5.9.6.  Disclaimer Objects

   Concrete disclaimer object definitions that reference the canonical
   text constants.

   ; ============================================================
